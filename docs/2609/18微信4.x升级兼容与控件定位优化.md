# 微信 4.x 升级兼容与控件定位优化

## 背景与问题描述

在微信 PC 客户端升级到全新 4.1.x 版本（实测当前版本为 `4.1.15.9`，采用全新 Qt 框架与 `Weixin.exe` 进程）后，原有的 UI 自动化查找微信窗口机制彻底失效：

### 1. 主窗口查找彻底失效
- **原逻辑**：`auto.WindowControl(searchDepth=1, Name="微信", ClassName='mmui::MainWindow')`
- **破坏性变更**：微信升级后，主窗口的 `ClassName` 虽然仍为 `'mmui::MainWindow'`，但窗口的 `Name`（标题）不再是固定的 `"微信"`，而是**当前登录微信账号的个人昵称**（例如当前环境为 `"LAVA"`）。
- **后果**：写死 `Name="微信"` 导致 `wx.Exists(0, 0)` 返回 `False`；快捷键 `Ctrl+Alt+W` 唤醒后再查找依然因为该条件匹配失败，抛出 `WECHAT_WINDOW_NOT_FOUND` 错误，整个自动化发送流程完全阻断。

### 2. UI 控件层级加深与时序容错
- **会话项（SessionCell）**：微信 4.x 实测深度已达 14 层，原先设置的 `searchDepth=15` 余量极小（仅 1 层），稍有容器外壳变动即面临截断风险。
- **聊天输入框（ChatInputField）**：实测深度为 17 层（`AutomationId="chat_input_field"`，`ClassName="mmui::ChatInputField"`）。且在切换会话后，右侧聊天面板加载有毫秒级渲染延迟，原先单次查找易发生偶发性未命中。

### 3. 自动化/沙箱子进程隔离桌面的“主窗口盲区”（Desktop Isolation）
- **现象**：在 Agent 子进程、Windows 服务、CI/CD 任务调度器或独立虚拟桌面环境下运行时，进程线程默认关联到系统派生的隔离桌面（例如 `Desktop: exebox-xxx`）。导致 Windows UIAutomation / Win32 API 检索到的桌面顶层窗口总数为 0，微信即使在前台正常运行也无法被发现，抛出 `WECHAT_WINDOW_NOT_FOUND`。
- **底层时序陷阱**：Windows 操作系统规定 `SetThreadDesktop` 必须在当前线程调用任何 UI/COM/窗口相关 API 之前执行；一旦执行了 `import uiautomation`，COM 初始化即会将当前线程永久锁定在当前隔离桌面，后续再调用 `SetThreadDesktop` 会直接报错（`ERROR_BUSY` 错误码 170）。

---

## 解决方案与改动细节

### 1. 挂载 Windows 交互式默认桌面 (`_attach_to_default_desktop`)
- 在 `scripts/wechat_controller.py` 和 `examples/wx.py` 最顶层（**必须在 `import uiautomation` 之前**），通过 Win32 API `OpenDesktopW("default", 0, False, 0x1FF)` 获取系统交互桌面的句柄，并调用 `SetThreadDesktop` 强制将执行线程绑定到 `default` 桌面。
- 引入模块级全局句柄缓存 `_cached_desktop_handle`，避免重复打开与句柄泄露。
- 在 `_get_wechat_window_result()` 中加入安全复核，确保在后台服务的多线程工作队列中也能正确关联到用户的真实桌面。

### 2. 主窗口跨版本多策略查找 (`_find_main_window`)
在 `WeChatController` 中将主窗口查找抽象为独立的多级兼容策略方法：
- **策略 1（微信 4.x 优先）**：`auto.WindowControl(searchDepth=1, ClassName='mmui::MainWindow')`
  - 解绑 `Name="微信"`，不论当前登录用户的昵称是什么（LAVA、张三、企业名等），均能稳定匹配。
- **策略 2（微信 3.x 兼容）**：`auto.WindowControl(searchDepth=1, ClassName='WeChatMainWndForPC')`
  - 向前兼容旧版微信 3.x 客户端。
- **策略 3（名称兜底）**：`auto.WindowControl(searchDepth=1, Name="微信")`

### 3. 搜索框与会话项定位鲁棒性增强
- **会话项**：将 `_activate_from_session_list_result` 和搜索后确认会话的 `searchDepth` 由 15 扩展到 25，确保深度冗余充足。
- **搜索框**：将搜索框 `searchDepth` 扩展到 25，并在 `Name='搜索'` 基础上增加 `ClassName='mmui::XValidatorTextEdit'` 兜底。

### 4. 聊天输入框重试与多级回退 (`_find_chat_input`)
- 搜索深度统一放宽到 25。
- 引入轻量重试循环（默认 3 次，每次间隔 0.15 秒），完美平滑会话切换后的 Qt 界面重绘延迟。
- 策略顺序：
  1. `AutomationId="chat_input_field"` + `ClassName="mmui::ChatInputField"` 精确匹配
  2. 单独 `AutomationId="chat_input_field"` 匹配
  3. 单独 `ClassName="mmui::ChatInputField"` 匹配
  4. 兼容旧版微信 3.x `Name="输入"` 控件

### 5. 示例与测试脚本更新
- 同步更新 `examples/wx.py`，增加桌面环境绑定并解绑 `Name="微信"`。
- 新增 `test/test_wx4_compatibility.py`，提供只读无干扰的微信兼容性快速验证测试。
- 更新 `README.md` 中关于微信主窗口属性与定位策略的说明。
