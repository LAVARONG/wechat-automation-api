# 微信发送时鼠标防抢夺与操作锁定研发说明

## 1. 背景与核心痛点

在以往的微信 PC 自动化发信过程中：
1. **鼠标指针乱飞/被强行拽走**：
   - 每次发送消息或切换会话时，底层 UI Automation 的 `Control.Click()` 会通过 Windows API `SetCursorPos` 将物理鼠标指针强行拉到微信窗口对应的控件中心并模拟点击。
   - 若用户正在进行其他工作（如写文档、画图、浏览网页、打字），鼠标光标会突然被拽走，造成强烈的视觉跳动与操作打扰。
2. **人机争夺与发错群风险**：
   - 如果自动化点击的瞬间，用户手正好在移动鼠标，鼠标物理坐标与自动化模拟坐标会产生冲突，可能导致点击偏离，甚至误点击其他联系人或按钮。

为彻底解决此问题，本次研发落地了 **方案 1（默认无感基础优化） + 方案 2（可选输入安全锁）** 双重保障架构。

---

## 2. 方案 1：默认无感基础优化（告别鼠标跳动）

### 2.1 原生 SetFocus 聚焦取代鼠标点击
- **原理**：UI Automation 原生提供 `IUIAutomationElement::SetFocus()` 接口。
- **改进**：聊天输入框激活彻底摒弃 `chat_edit.Click()`，封装 `_focus_chat_input(chat_edit)`：
  1. 优先调用 `chat_edit.SetFocus()`，直接请求系统将键盘焦点赋予输入框。**整个过程物理鼠标指针不发生任何移动，零位移、零闪烁**。
  2. 若控件在极个别特殊状态下未响应 `SetFocus`，平滑回退至安全点击兜底。

### 2.2 毫秒级坐标快照与瞬发复位（Save & Restore Cursor）
- **原理**：针对部分自绘列表项或复合控件必须通过物理点击激活的场景（如左侧会话列表 `session_item`、搜索结果项 `matched_item`）：
  1. 会话激活前显式执行 `wx.SetActive()`，确保后台状态下的微信窗口正确响应点击与会话切换；
  2. 全局设置 `auto.MAX_MOVE_SECOND = 0`，禁用 `uiautomation` 默认长达 1 秒的缓慢鼠标平滑滑动动画；
  3. 点击前通过 `GetCursorPos` 记录用户当前物理光标坐标；
  4. 采用 `control.Click(simulateMove=False, waitTime=0.05)` 进行毫秒级瞬发点击，消除一切移动等待延时；
  5. 在 `finally` 块中立即调用 `SetCursorPos` 将鼠标光标原路瞬时复位到用户手中。
- **效果**：单次点击由原本的 1.5 秒缓慢拖拽压缩到 100ms 左右，鼠标瞬移点击并在完成动作后秒速归位，彻底告别光标慢速滑行动画。

## 3. 方案 2：操作期防误触安全锁（可选配置）

为满足对稳定性要求极高的批处理、重要通知发送场景，增加了操作期间临时锁定鼠标与键盘输入的选项。

### 3.1 双层防御与权限自适应
- **第一层：`ClipCursor` 范围约束（免提权）**
  - 使用 Windows 原生 `user32.ClipCursor(&RECT)` 将鼠标光标约束在当前坐标的 $1 \times 1$ 像素微矩形内。
  - **特性**：普通用户权限即可生效，发信期间用户即使意外推移鼠标，光标也无法移动，彻底杜绝人机位移冲突。
  - **自动化点击穿透兼容**：在 `_safe_click` 执行点击时，内部临时释放 `ClipCursor(None)` 允许系统光标移动到目标控件，点击完成且光标复位后再次加锁，兼顾了输入锁定与自动点击。
- **第二层：`BlockInput` 硬件阻断（提权生效）**
  - 尝试调用 Windows `user32.BlockInput(True)`，在系统底层暂时屏蔽键盘与鼠标硬件事件。
  - **特性**：若以管理员身份运行 Python 则全系统完全屏蔽；若非管理员则平滑由 `ClipCursor` 兜底。
- **安全兜底机制**：
  1. 使用 Python 上下文管理器（`with self._safe_input_lock():`），无论正常发送完毕还是发生未捕获异常，`finally` 块保证 100% 执行 `ClipCursor(None)` 和 `BlockInput(False)` 并复位光标，绝不锁死电脑。
  2. Windows 系统级安全快捷键 `Ctrl + Alt + Delete` 为内核级保留中断，在任何极端异常下均可强制唤醒解除。

### 3.2 可重入保护设计
- `WeChatController` 内部维护 `_input_lock_depth` 重入计数器。
- 当外部调用组合方法 `search_and_send_result` 时，外层进入锁定；内部调用的 `search_contact_result` 和 `send_message_result` 自动识别已处于锁内，避免重复加锁和闪烁解锁；直到整个发信流程结束后一次性完整释放。

## 4. 配置与使用指南

### 4.1 配置文件 `config.json`
在 `config.json` 中已加入全新配置项 `lock_mouse_during_send`：
```json
{
    "token": "your_secret_token_here",
    "host": "127.0.0.1",
    "port": 8808,
    "message_interval": 1,
    "lock_mouse_during_send": false,
    "log_level": "INFO",
    "log_file": "wechat_automation.log"
}
```
- `"lock_mouse_during_send": false`（默认）：仅启用**方案 1**（无感 SetFocus + 鼠标瞬时复位），日常发信完全不抢光标，也不锁定用户操作。
- `"lock_mouse_during_send": true`：同时启用**方案 1 + 方案 2**，在发信的大约 1 秒关键窗口期内临时锁定鼠标/键盘，发完立即解锁。

### 4.2 命令行工具 `skill_cli.py`
支持在命令行传参临时覆盖全局配置：
```powershell
# 临时开启锁定（适用于重要发送任务）
python scripts/skill_cli.py --to "文件传输助手" --content "测试发信" --lock-mouse

# 临时关闭锁定（使用默认无感操作）
python scripts/skill_cli.py --to "文件传输助手" --content "测试发信" --no-lock-mouse
```

### 4.3 Python 代码中直接调用
```python
from wechat_controller import WeChatController

# 方式 1: 自动读取 config.json 配置
controller = WeChatController()

# 方式 2: 显式开启发信锁定
controller = WeChatController(lock_mouse_during_send=True)
controller.search_and_send_result("文件传输助手", "测试消息")
```
