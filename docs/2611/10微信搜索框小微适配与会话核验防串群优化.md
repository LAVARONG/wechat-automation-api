# 微信搜索框小微适配与会话核验防串群优化

## 背景与问题描述

在微信 PC 客户端升级过程中，微信向部分账号灰度上线了“小微 AI”（左侧具有独立的 `mmui::ChatBotButton` 控件）。该项变更对原有 UI 自动化带来了显著影响，并暴露出两个关键隐患：

### 1. 搜索框未聚焦态形态变更导致搜索报错（`SEARCH_BOX_NOT_FOUND`）
- **原逻辑**：`wx.EditControl(Name='搜索', searchDepth=25)` 与 `wx.EditControl(ClassName='mmui::XValidatorTextEdit', searchDepth=25)`。
- **破坏性变更**：
  - 在加入“小微 AI”按钮后，顶层搜索区域布局变更为：`[Button: 小微] [Group: 搜索] [Button: 添加(+)]`。
  - **在被激活/点击前，搜索框在 UI 树中不再是一个 `EditControl`**，而是 `GroupControl(Name='搜索', ClassName='mmui::XHBoxView')`，内部仅包含一个文本占位符 `TextControl(Name='搜索', ClassName='mmui::XTextView')`。
  - 只有在获取焦点后，Qt 框架才会动态实例化或挂载真实的输入框 `EditControl(ClassName='mmui::XValidatorTextEdit')`。
- **后果**：直接通过 `wx.EditControl(...)` 探测搜索框必定返回 `False`，抛出 `SEARCH_BOX_NOT_FOUND`；如果使用固定坐标点击，极易偏左误触“小微 AI”按钮弹出 AI 对话框。

### 2. 搜索不到目标时误回车与串群重发风险（业务严重隐患）
- **现象**：当搜索一个不在常用列表中的联系人/群聊，或者仅为部分模糊匹配时：
  - 微信 4.x 弹出的浮层 `mmui::SearchContentPopover` 中可能会展示“聊天记录”、“搜索网络结果”、“网络查找微信号：”等与联系人会话无关的项。
  - 旧代码仅在输入后盲目发送 `{Enter}`，当没有联系人完全匹配时，回车会直接进入“网络搜索结果”或弹出好友申请浮层；
  - 甚至在切换会话失败时未能识别，导致继续执行发送动作，将准备发往群 B 的内容错发到了当前停留在窗口的群 A 中（串群事故）。

## 解决方案与技术实现

### 1. 跨版本搜索框激活与定位 (`_activate_search_box`)
在 `WeChatController` 中实现统一搜索激活机制：
- **策略 1（全版本快捷键优先）**：
  - 激活微信窗口后，优先发送微信官方原生通用快捷键 `Ctrl+F`。
  - 微信瞬间唤醒并聚焦 `mmui::XValidatorTextEdit` 输入框，彻底避开由于小微 AI 按钮存在导致的鼠标点击偏移风险，且无缝兼容微信 3.x 与 4.x。
- **策略 2（多态控件探测兜底）**：
  - 若快捷键未捕获，依次探测多态容器：`EditControl(Name='搜索')` -> `GroupControl(Name='搜索')` -> `Control(Name='搜索')`。
  - 找到后执行 `.Click()` 激活，再获取生成的 `mmui::XValidatorTextEdit`。
- **状态清理**：激活后自动执行 `{Ctrl}a{Back}` 全选删除残留内容，避免上次搜索关键词干扰。

### 2. 搜索分组白名单过滤与完全匹配算法
在搜索弹窗 `mmui::SearchContentPopover` 的 `search_list`（`mmui::XTableView`）遍历中：
- **白名单业务分组**：`最常使用`、`联系人`、`群聊`、`功能`（例如文件传输助手）、`服务号`。
- **黑名单严格过滤**：严禁匹配 `聊天记录`（`mmui::SearchMessageCellView`）、`搜索网络结果`、`网络查找微信号：`、`收藏`。
- **完全精确匹配规则**：
  - 目标项文本必须与 `target` 完全一致（`name == target`）；
  - 或其 `AutomationId` 严格等于 `search_item_{target}`、`search_item_function_{target}`、`search_item_contact_{target}`、`search_item_group_{target}` 等。
- **未完全匹配熔断机制**：
  - 若在允许分组下未找到完全匹配项，**绝对不按回车**！
  - 立即发送 `{Esc}` 干净关闭搜索浮层，返回错误码 `CONTACT_NOT_FOUND`，从根源上阻止误发。

### 3. 会话核对与防串群终极校验机制 (`_verify_active_chat`)
无论是通过左侧会话列表直接激活，还是通过搜索框点击项进入会话，均必须经过 `_verify_active_chat` 校验：
- **核对策略 1**：核对右侧聊天输入框 `chat_input_field` 的 `Name` 属性（微信 4.x 实测 Name 严格等于联系人/群聊名称，不含群人数后缀）。
- **核对策略 2**：核对窗口顶部中央大标题控件 `current_chat_name_label` 的 `Name` 属性。
- **核对策略 3**：核对左侧会话项 `session_item_{target}` 是否处于选中状态（`IsSelected == True`）。
- **双重拦截（Double Insurance）**：
  - 在 `search_contact_result` 切换后核验：不匹配则直接返回 `TARGET_VERIFY_FAILED`。
  - 在 `send_message_result`、`send_picture_result`、`send_file_result` 物理发送前传入 `expected_contact` 二次复核：若当前活动窗口不是预期目标，立刻抛出 `TARGET_MISMATCH_ABORT` 紧急终止，彻底杜绝串群现象！

## 验证结论

1. **兼容性诊断测试 (`test/test_wx4_compatibility.py`)**：
   - [测试 1] 微信主窗口获取：成功匹配 `mmui::MainWindow`；
   - [测试 2] 搜索框激活与定位：成功唤醒并定位到 `mmui::XValidatorTextEdit`；
   - [测试 3] 会话项控件识别：成功遍历会话项（包括置顶群聊与文件传输助手）；
   - [测试 4] 聊天输入框探测：精准定位 `ChatInputField`；
   - [测试 5] 防串群机制验证：同名校验成功通过，异名验证被百分之百拦截阻断。
2. **搜索容错与防误发实测**：
   - 搜索完全不存在的联系人（如 `不存在的用户测试123456789`）：触发安全退出，返回 `CONTACT_NOT_FOUND`，未按回车，未发送任何消息。
   - 搜索部分模糊词（如 `就买酒`）：未在允许分组命中完全匹配项，安全退出并拦截，防止误发到相似群组。
   - 搜索完全匹配项（如 `就买酒电商自动优惠线报1`、`文件传输助手`）：精准定位点击并校验通过。
3. **真实环境发送验证**：
   - 执行 `python scripts/skill_cli.py --to "文件传输助手" --content "微信小微适配与防串群核验测试成功" --no-api --json`：全流程耗时约 3 秒，安全核验通过并成功送达。
